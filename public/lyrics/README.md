# 歌词目录

放 `.lrc` 格式的歌词文件，**一首歌一个文件**，文件名 = 歌单里的曲目 id（例如 `ivory-tower.lrc`）。

## 怎么用（推荐：`npm run lyrics`）

不用手工搬文件，也不用手工改代码 —— 脚本两头都管：

1. **先生成待填模板**（按 `src/lib/music.ts` 里的歌单，一首一个，模板顶部写清了是哪首歌）：

   ```bash
   npm run lyrics:init
   ```

2. 把歌词粘进 `lyrics-src/*.txt` —— **注释行（`#` 开头）下面直接贴，一行一句**。
   已经有带时间轴的 LRC 的话，整段贴进去也认（`[00:12.34]这是一句歌词`）。

   > 文件名也可以用歌单里的**标题**而不是 id，两种都匹配：
   > `lyrics-src/还是分开.lrc` / `lyrics-src/ivory-tower.lrc`

3. 导入：

   ```bash
   npm run lyrics
   ```

脚本会做三件事：

- 复制成 `public/lyrics/<id>.lrc`，并自动补上 `[ti:]` / `[ar:]` 元信息
- 在 `src/lib/music.ts` 对应条目里插一行 `lyrics: lyricSrc("<id>.lrc"),`
- 已经登记过的只更新文件，不重复写

**没填的模板会被跳过**（去掉注释后没正文就算没填），不会生成一堆空歌词文件；
跑完会告诉你还剩几首待填。文件名对不上的也会单独列出来。

## 手工加（也可以）

1. 把 `xxx.lrc` 放进这个目录
2. 在 `src/lib/music.ts` 的歌单里给那首曲子加一行 `lyrics`：

   ```ts
   {
     id: "my-song",
     title: "歌名",
     artist: "歌手",
     src: withBasePath(musicUrl("my-song.mp3")),
     lyrics: lyricSrc("xxx.lrc"),   // ← 这一行
   }
   ```

**不填 `lyrics` 也完全没问题** —— 歌词窗会显示「这首歌还没有歌词」，不会报错。

## LRC 怎么写

```text
[ti:曲名]
[ar:歌手]
[offset:0]              整体偏移，单位毫秒，正数表示歌词延后

[00:00.00]第一句
[00:12.34]第二句
[01:02:00]一分零二秒
```

解析器（`src/lib/lyrics.ts`）认这几种时间写法：

| 写法 | 含义 |
| --- | --- |
| `[mm:ss.xx]` | 百分秒（最常见） |
| `[mm:ss.xxx]` | 千分秒 |
| `[mm:ss:ff]` | 帧（百帧制） |
| `[00:10.00][01:20.00]副歌` | 一行多个时间标签（重复段/合唱） |

**没有时间轴的纯文本歌词**不会被丢 —— 会整段显示出来（不滚动、不高亮）。
`npm run lyrics` 遇到 `.txt` 就是按这个处理的。

## 注意

- 文件要存成 **UTF-8**。带 BOM 也能读（解析器会先去掉），但别存 GBK。
- **歌词是受版权保护的作品。** 博客是公开仓库，往这里提交歌词等于**公开分发**。
  只放你有权利放的内容：自己写的、已授权的，或公有领域的。
  脚本**不会**去任何网站抓取歌词 —— 歌词文本需要你自己提供。
